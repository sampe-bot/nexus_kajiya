# HTML読み込みの実装方針

決定日: 2026-11-18。この方針に基づく初版を実装済みです。ブラウザ計測で対応部分を変換し、JSON形式で保存します。

## 採用する方式

**静的HTMLの対応部分をDocument Modelへ変換してから、既存エディターで編集する。** 初版はテキスト中心のスライドを対象にする。

```text
HTMLファイル
  → HTML / CSSの解析と許可対象の再構築
  → 隔離したブラウザ領域でレイアウトを計測
  → Document Model v2へ変換・検証
  → 変換後プレビューと取り込み結果の確認
  → 文書を置き換えて編集
```

JSONを正本とする既存設計を維持する。取り込み後の保存形式もJSONとし、元HTMLのDOM・CSS・JavaScriptを編集状態として保持しない。元ファイルは変更しない。

HTML全体を表示するだけの機能では、現在のテキスト移動・編集に接続できない。一方、任意のHTMLを完全に再現するには、現在のモデルにない画像・図形・装飾・動的挙動まで必要になる。初版は対応範囲を明示した変換機能として実装する。

## 初版の対応範囲

| 項目 | 方針 |
| --- | --- |
| 入力 | UTF-8の単一`.html` / `.htm`ファイル。既存JSON読み込みも維持 |
| スライド識別 | `data-nexus-slide`付き要素を優先し、なければ`.slide`。両方なければ`body`を1枚として扱う。スライドルートの入れ子はエラー |
| ページ分割 | 明示されたスライド単位のみ。長いWebページの自動分割は行わない |
| サイズ | 960 × 540へ統一。1920 × 1080等の16:9は等比縮小。別比率・領域外へのはみ出しは理由を示して取り込みを中止 |
| 複数スライド | 文書順で変換し、全ページを確認・編集できる最小限の切り替えUIも含める |
| 編集対象 | 見出し、段落、単純なリスト、テキストを含む`div` / `span`等をテキスト要素へ変換。改行と文字の順序を保持 |
| レイアウト | 通常フロー・絶対配置・単純なflex / gridをブラウザで計測し、要素の固定座標へ変換。編集後の自動再配置は行わない |
| CSS | 埋め込み`style`とインラインCSSから、配置計測と対応スタイルに必要な宣言を扱う。対応する文字色・サイズ・太さ・行間・左右揃え、スライドの単色背景をモデルへ保存 |
| フォント | アプリ共通フォントへ統一してから計測。フォント置換や文字装飾の簡略化を取り込み結果に表示 |
| 画像・図形・表等 | 初版では変換対象外。対象と件数を表示し、変換後のプレビューを確認してから取り込む |
| 動的HTML | スクリプトを実行しない。JSで生成されるスライドは取り込めない |
| 外部リソース | 外部CSS・フォント・画像、相対パスの関連ファイルを取得しない。必要なリソースが除外されたことを表示 |

初版で保証するのは、対応部分を編集可能な状態に変換すること。元HTMLの完全な見た目、レスポンシブ挙動、元コードの復元は保証しない。

サイズ計測では`aspect-ratio`、`inset`、CSS変数、`container-type` / `container-name`も保持する。静的な内容がHTML内にあり、ページ切り替えのために非表示になっているスライドルートは、計測時に表示状態へ変更して取り込む。JSで内容自体を生成する資料は引き続き対象外とする。透明なスライド背景は、祖先の単色背景を参照してから白へフォールバックする。

## 変換ルール

1. HTMLを構文解析し、明示的に許可した要素・属性・CSSだけで計測用文書を作る。正規表現だけでHTMLやCSSを解析しない。
2. スライドのルートと元のサイズを確定する。`body`を使う場合の計測ビューポートは960 × 540とする。領域外の内容を黙って切り落とさない。
3. 共通フォントを適用し、各スライドを個別に計測する。非表示にする場合も`display: none`を使わず、レイアウト可能な領域を用意する。
4. テキストを含むコンテナと子要素の二重抽出を防ぐ。親の直接テキストも落とさず、連続したインラインテキストをまとまりとして扱う。`br`は改行、単純なリストの記号は文字として保存する。非表示テキストは除外する。
5. paddingやmarginを含むコンテナ全体ではなく、文字の配置領域を要素フレームへ変換する。スライド内の相対座標と文字サイズを同じ倍率で960 × 540へ正規化する。
6. CSSの色を6桁HEXへ変換する。太さ・行間などをv2の許容値へ近似する場合は警告する。部分的な太字・色分けは単一スタイルへ簡略化し、その旨を示す。
7. 背景装飾、罫線、影、疑似要素、回転、複雑な重なりなど、再現しない表現も取り込み結果へ記録する。ルート背景が透明なら白を既定値として、その適用を表示する。
8. スライド・要素のIDを文書全体で一意に採番し、`safeParseSlideDocument`で検証する。境界違反を隠すための自動切り取りはしない。

変換結果は`document`と`warnings`、失敗結果は`errors`を持つ判別可能な型にする。警告にはスライド番号・対象・理由を含める。警告は一時的な取り込み情報として扱い、初版ではv2の保存スキーマを変更しない。

## ブラウザへの配置

HTMLの構文解析には`parse5`、CSSの解析には`css-tree`を採用する。ASTから許可対象だけを再構築し、元HTMLを直接アプリのDOMへ挿入しない。両ライブラリは構文解析を担当し、許可・拒否の判断はImporter側で行う。[parse5公式](https://parse5.js.org/functions/parse5.parse.html)、[CSSTree公式](https://github.com/csstree/csstree)

計測用iframeは`sandbox="allow-same-origin"`とし、`allow-scripts`を付けない。親側からDOMを計測できる構成にする。iframe内でスクリプトを実行する必要はない。[iframeの仕様説明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

計測用文書には、インラインCSSだけを許すCSP（`default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'`）を本文より先に設定する。`script`、イベント属性、`iframe`、`object`、`embed`、`base`、入力由来の`meta`や外部参照を持ち込まない。CSSの`@import`、URL参照、アニメーションも除外する。ファイル5MB・20,000ノード・入れ子100階層・100スライド・1枚2,000テキスト・計測5秒の上限を設け、成功・失敗・キャンセル時に計測領域を破棄する。[CSPの説明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)

`DOMParser`だけを安全性の根拠にしない。解析した文書で画像等のリソース取得が起き得るため、ブラウザ文書へ配置する前にASTから入力を絞り込む。[DOMParserの注意事項](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString)

## 画面の動き

1. ツールバーに「HTMLを読み込む」を追加する。
2. ファイル選択後、現在の編集文書とは別に変換候補を作る。
3. 変換後のスライド、枚数、編集できる要素、除外・簡略化した内容を表示する。複数枚なら全ページを切り替えて確認できる。
4. 「この内容で取り込む」で文書を一括置換する。JSON保存を案内し、未保存の編集がある場合は現在の内容が置き換わることを明示する。
5. 中止・解析失敗・検証失敗では、編集中の文書と選択状態を維持する。テキスト要素が1つも得られないスライドはエラーとして扱う。

警告の確認は製品の取り込みフローとして実装する。実装作業そのものを承認待ちにする趣旨ではない。

## 変更箇所と実装順

| 順序 | 対象 | 内容 |
| --- | --- | --- |
| 1 | `src/importers/`（新設） | HTML / CSSの解析・再構築、スライド識別、変換結果の型とサンプル入力を追加 |
| 2 | `src/importers/`、`SlideRenderer.tsx`、`styles.css` | ブラウザ計測とv2変換を実装。モデルにない固定の帯・ロゴ・フッターをRendererから除去し、計測結果と表示の文字位置を合わせる |
| 3 | `App.tsx`、`SlideEditor.tsx` | `activeSlideId`で編集対象を指定し、プレビューとエディターに最小限のスライド切り替えを追加。切り替え・文書置換時に旧要素の選択・編集中状態をリセット |
| 4 | `App.tsx`、取り込み確認UI（新設） | HTML用ファイル入力、候補プレビュー、警告、適用・中止を接続 |
| 5 | テスト、サンプル、README | 受け入れ条件を検証し、対応HTMLと制限を公開 |

要素型の追加、全編集操作のCommand化、スライドの並べ替え等は初版の前提にしない。既存のv0.2計画と機能単位で接続する。履歴基盤がある場合、取り込み確定は文書置換1回として履歴へ記録する。未実装のUndoを取り込みフローで約束しない。

## 受け入れ条件

- 見出し・本文・改行・単純なリストを持つ静的HTMLを取り込み、移動とインライン編集ができる。
- 960 × 540と1920 × 1080の対応サンプルが同じ座標・文字サイズへ正規化される。
- 埋め込みCSS、入れ子テキスト、余白、flex / gridを含む代表サンプルで、重複抽出・文字欠落・意図しない縦位置ずれがない。
- 複数スライドを切り替えて編集でき、編集が他のページへ混ざらない。
- 画像・外部CSS・JS依存等の非対応内容を、取り込み確定前に把握できる。
- スクリプト・イベント属性が実行されず、HTML / CSS由来の外部通信が発生しないことをブラウザテストで確認する。
- 非16:9、領域外要素、入れ子スライド、空の変換結果、上限超過、途中キャンセルで既存文書が壊れない。
- 変換後にJSON保存・再読み込みすると、内容と配置が維持される。既存v1 / v2 JSONの読み込みも維持する。
- パーサーと変換処理はVitest、計測・表示・通信遮断・主要操作は実ブラウザで検証し、`npm run check`が成功する。

## 次の拡張

初版の実HTMLサンプルで不足を確認した後、画像・図形・表・リッチテキストを必要順にモデルへ追加する。保存形式を拡張する際はバージョンと移行処理を用意する。

静的HTML出力を実装する段階では、出力HTMLへDocument Model JSONを埋め込み、再読み込み時は埋め込みモデルを検証して復元する。自アプリの出力はこの経路で正確に復元し、外部HTMLの近似変換とは区別する。
